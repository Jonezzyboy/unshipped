          Argo CD

          The Deployed column reads your Argo CD applications and shows where each repo is running. Three things have to line up — this page checks each one.

          1. 1

            Reach the server

            The address you open the Argo CD web UI on — not the gRPC port.

            Identity tokens are minted from your local gcloud login and refreshed hourly, so gcloud auth login has to have been run on this machine. Leave the service account empty only if gcloud is already signed in as one that IAP admits.

          2. 2

            Sign in to Argo CD

            Argo CD wants an identity of its own. The credential is stored in your OS keychain, never in the settings file.

            IAP only gets the request through the proxy — it is not an Argo CD login.

            or paste an API token

            On an SSO-only server there is no local password — make a token under Settings → Accounts → your account → Generate New. The account needs applications, get and applications, list.

          3. 3

            Link applications to repos

            An application lands on a repo's row when one of its sources' repoURL is that GitHub repo. When it isn't — a chart repo, a config mirror, a repo split across several apps — say so on the Argo side with an annotation:

            An annotation always wins over the source URL.
